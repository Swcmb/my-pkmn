# Pokémon TCG Agent：模型优化、用户训练门禁与自动导出

## 一、项目目标

项目路径：`D:\pkmn-kaggle`

Python 解释器：`D:\ProgramFiles\deeplearning\python.exe`

硬件：NVIDIA RTX 5060 Laptop，8GB 显存。

平台卡牌库与本地 `cards.csv` 已由用户确认一致。固定使用比赛提供的 1267 张卡牌，不再将扩充卡池作为前置任务。

目标：在比赛规定的 Agent 接口、卡组规则和沙箱资源限制下，获得竞争力强、稳定性高、经过真实评测的最终 Agent。

## 二、执行权限与硬性门禁

### AI 可以自主执行

- 检查 Git 状态、项目结构、代码和现有实验产物。
- 检查卡牌数据、卡组合法性、checkpoint 与模型加载逻辑。
- 修复有证据支持的问题，并补充回归测试。
- 运行代码审计、单元测试、接口测试和不需要启动训练的评测。
- 准备训练配置、训练命令、运行说明和资源预估。
- 检查现有模型、比较已有评测结果、制定晋级门禁。
- 在用户完成训练并明确确认候选模型后，运行训练后评测。
- 在最终模型通过门禁后，自主执行最终导出、文件完整性检查和 SHA-256 校验。

### 训练必须由用户亲自运行

这是不可违反的硬性要求。

1. AI 不得启动任何训练任务。
2. AI 不得通过 PowerShell、Python、后台进程、任务计划、工作流或其他方式间接启动训练。
3. AI 可以检查训练脚本、运行 `--help`、准备参数和验证配置，但不得执行会真正开始训练的命令。
4. AI 必须提供完整、可复制的训练命令，并说明运行目录、输出位置、预计耗时、资源峰值风险、停止方式及完成后的检查步骤。
5. 提供命令后，等待用户亲自运行。
6. 用户报告训练完成或提供训练产物后，AI 才继续训练后评测。
7. 如果用户尚未完成训练，不得假定新 checkpoint 已生成，也不得提前将其设为最终模型。

### 导出允许 AI 执行

与训练不同，最终导出不需要用户亲自运行。

1. 在用户训练完成、候选 checkpoint 确认、训练后评测通过后，AI 可以自主执行最终导出。
2. 执行前必须检查真实导出脚本及其参数，确认不会覆盖旧提交包或其他重要文件。
3. 导出只能使用通过门禁的模型和合法牌组。
4. 导出后必须检查文件结构、入口、牌组、必要资源、文件大小和 SHA-256。
5. 如果门禁不通过，禁止将未通过的候选模型导出为正式提交包；应说明原因并等待进一步决策。
6. 不得声称未实际生成或验证的文件已经完成。

## 三、阶段 0：审计当前环境

首先审计：

- Git 分支、工作区状态和未提交修改。
- `cards.csv` 的真实路径、SHA-256、字段、唯一 ID 数量。
- 当前 Agent 入口、训练脚本、模型架构、牌组加载逻辑。
- 现有 checkpoint、训练日志、评测结果、牌组候选和提交包。
- 单元测试、接口测试和沙箱测试的现状。
- GPU 显存、内存、磁盘空间及训练资源限制。

如果历史产物存在，优先核实：

- `runs\train-20m-e16-1m\ckpt_999424.pt`
- `runs\evaluation\card_database_migration\best_deck.csv`
- `submission_rl_transformer2_db_migrated.tar.gz`

以上只是待核对的历史路径。必须以实际文件、哈希和运行结果为准。

不要覆盖原 checkpoint、原牌组或已有提交包。新实验使用独立输出目录。

## 四、阶段 1：卡组、Agent 和沙箱审计

依据官方规范检查最终牌组：

- 恰好 60 张有效卡牌。
- 所有 ID 均存在于比赛卡牌库。
- 至少一张真正的基础宝可梦。
- 按名称统计同名卡最多 4 张，基础能量除外。
- ACE SPEC 全牌组最多一张。
- 卡组的宝可梦、进化链、能量和策略卡配置合理。

检查 `main.py` 是否满足：

`agent(obs_dict: dict) -> list[int]`

重点验证：

- `select is None` 的兼容处理。
- 所有 `SelectType` 和 `SelectContext` 的选择逻辑。
- 返回数量、下标合法性与下标唯一性。
- `PLAY` 使用手牌索引定位卡牌。
- `ATTACK` 使用 `attackId` 查询招式。
- `ATTACH`、`EVOLVE`、弃牌、检索、能量、奖赏卡和特殊状态选择。
- 不访问对手隐藏手牌。
- 不出现越界、崩溃、无限循环或超时风险。

运行现有测试及必要的回归测试。发现缺陷时先记录证据，再做最小可回滚修复。

官方限制：单步默认 100ms、单局 10 分钟、内存 2GB、CPU 2 核。测试必须尽可能覆盖这些约束。

## 五、阶段 2：建立模型评测基线

重新核实旧模型与候选模型的实际表现。

尽量在相同卡组、引擎、对手、种子集合和胜负口径下比较：

1. 随机合法 Agent。
2. 同架构未训练模型。
3. 旧 checkpoint。
4. 自对弈镜像测试。
5. 可用的强基线或不同策略对手。

每组尽可能至少 120 局。记录胜率、胜负平局、置信区间、非法动作、超时和崩溃。

历史报告曾记录：

- 对随机对手 73/120 胜。
- 对同配置未训练模型 100/120 胜。
- 自对弈 61/120 胜。
- 对旧模型 61/120 胜。

这些数字必须视为待复核数据，不得直接当作本次实验结果。若无法复现，明确记录差异。

不要把自对弈接近 50% 当成模型强度的独立证据。

## 六、阶段 3：准备训练方案，但绝不启动训练

审计训练脚本、参数语义、初始化逻辑、checkpoint 加载方式、输出目录和牌组池。

历史候选方案为从：

历史参考参数：

- `--total-timesteps 500000`

上述参数只是候选配置，不得直接假设它们与当前脚本兼容。

先通过 `--help` 和源代码核实每个参数的存在、含义和组合合法性。检查训练牌组池是否包含最终牌组，以及是否存在 `--finetune-deck` 与 `--gate-decks-file` 参数语义不匹配的问题。

如有必要，准备对 `rl/decks_train.py` 的最小修改方案，备份原配置，并保证评测数据独立。

### 输出完整训练执行说明

准备好后，向用户提供：

1. 最终建议的训练配置及每个关键参数的理由。
2. 完整 PowerShell 训练命令。
3. 训练输出目录和 checkpoint 预计路径。
4. 预计耗时、显存与内存风险。
5. 训练日志监控方法。
6. 如何安全中止训练。
7. 训练完成后需要提供给 AI 的日志、checkpoint 和评测产物。

**此阶段只准备命令，绝不运行训练命令，也不启动任何训练进程。**

随后停止，等待用户亲自运行训练并告知结果。

## 七、阶段 4：用户训练完成后进行评测

只有用户亲自运行训练并确认训练完成后，才进入此阶段。

AI 应自主检查新 checkpoint 是否存在、文件是否完整、训练是否异常结束，以及架构和模型参数是否匹配。

然后运行训练后评测，与旧 checkpoint 使用一致的对照条件进行比较。

晋级至少要求：

- 牌组合法、Agent 接口兼容。
- 关键测试通过。
- 门禁对局中没有非法动作、崩溃或超时。
- 对随机对手没有无法解释的明显退步。
- 对同架构未训练模型有稳定优势。
- 对旧 checkpoint 的独立评测能够证明有意义的提升。
- 评测样本量和置信区间足以支持结论。

不要盲目套用历史阈值。必须结合本次实际基线、对手和评测条件解释晋级结果。

若候选模型没有稳定提升，保留旧模型作为回退版本，并说明失败原因。不得强行晋级。

## 八、阶段 5：最终导出与验证

用户完成训练且候选模型通过阶段 4 的晋级门禁后，AI 可以自主完成最终导出。

操作顺序：

1. 确认最终 checkpoint、`main.py` 和 `deck.csv`。
2. 确认卡组满足全部比赛约束。
3. 检查真实打包脚本和导出参数。
4. 确认输出路径，不覆盖旧提交包。
5. 执行正式导出命令。
6. 检查 `submission.tar.gz` 的实际内容和目录结构。
7. 验证 `main.py` 入口、`deck.csv` 的 60 张卡、模型加载依赖和必要资源。
8. 在可用的官方等价环境下运行最终 smoke test。
9. 计算最终文件 SHA-256 和大小。
10. 输出可追溯的交付报告。

如果导出或校验失败，定位问题并修复后重试，但每次重试都必须检查是否会覆盖现有有效文件。

导出不是训练。**允许 AI 在满足前置条件后实际执行导出，而不是仅提供导出命令。**
