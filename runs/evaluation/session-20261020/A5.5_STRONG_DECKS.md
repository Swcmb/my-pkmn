## 2. 还原方法（§8.3，已执行）

纯文本统计推断，不依赖"同 seed 可本地复现平台对局"这个未验证假设。

日志实测格式决定了三条口径（每条都是先写错、再用真实日志查出并修正的）：

| # | 缺陷 | 症状（修正前的错误证据） | 修正 |
| :-- | :-- | :-- | :-- |
| 1 | 按 `▶` 块头继承侧别 | 对手卡漏进本队：bug 队出现 Abra、超能队出现 Bug Catching Set；`Basic {G} Energy` 单局"上限"222 | 每条事件行自带 `A 方`/`B 方`，按**行首**归属 |
| 2 | 同一动作数两遍 | `▶ A 方：打出「Dawn」` 与 `A 方 打出「Dawn」` 各计一次，打出次数整体翻倍 | 只数**结算行**（行首无 `▶`） |
| 3 | 附能误含工具 | `Hop’s Choice Band` 附能 119、`Hero’s Cape` 附能 24 被当成能量 | 只保留 `cardType∈{5,6}` |
| 4 | ACE SPEC 自检加的是 cardId | 报告 "ACE SPEC 1159" | 按张数求和 |
| 5 | 名额全给卡名 | 15 种 ×4 = 60，能量 0 张 | 先扣能量预算再分配卡名名额 |

张数证据按强度分级：`场面同局最大同时张数`（硬下界，来自 `场面` 块的出战/备战行）>
`单局打出最大次数`（近似下界）> `p`（出现局数占比，只决定入选与补齐）。
`抽到次数` 会被 Dunsparce/Bug Catching Set 这类洗回牌库的效果重复触发，**只展示不参与定张数**。

能量张数在日志里不可辨识（看不到牌库余量），只能用先验：
`E_target = clip(round(1.5 × 每局附能次数 p75), 10, 20)`，系数 1.5 是"用掉的之外还得留备料"的经验值，
**属于推断**。日志一种基础能量都没出现时（对对对队），按牌组内宝可梦的 `energyType` 补一张对应基础能量，
该卡在证据表里单独标记 `属性兜底（日志未出现，先验）`。
