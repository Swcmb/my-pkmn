- **完全未覆盖**：§五 第 5 项"可用的强基线或不同策略对手"

### 2.2 为什么不复用现成脚本

`stage5_gates.py` 顶部 `OUT = os.path.join(HERE, "stage5_gates.json")` 是**硬编码路径**，直接改 `GATE_GAMES/GATE_SEEDS` 环境变量重跑会覆盖既有 840 局的原始记录。因此我把它的协议原样搬到新脚本，输出到自己的目录，并做两件事保证可合并：

2. **种子不重叠**：既有 `20261020/20261021`，补测用 `20261022/20261023`，二次补测用 `20261024`

新脚本 `stage2_supplement.py`（10 格 × 60 局 = 600 局）。除补齐样本外，加了两格原矩阵没有、但对判断"模型是否变强"更关键的对照：

- `cand_vs_baseline_mirror`：两座位都驾驶 `best_deck.csv` 的**纯 net-vs-net**。原矩阵只有 74 副混合池的 `cross` 模式，那条臂里两个模型各驾驶不同牌组，牌组强度差会稀释模型差。

## 3. 工作包 B：阶段 4 门禁执行器的编写与三个隐藏缺陷

目标：让你回报训练完成后，阶段 4 是**一条命令**而不是一堆临时拼装。产物 `phase4_gate.py`，对应任务书 §七 的 7 条晋级要求，逐项实现为 G1–G8 + G7b + 自镜像 sanity。

### 3.1 先摸清可复用的评测面

| 工具 | 核实结论 |
|:---|:---|
| `runs/evaluation/eval_h2h.py` | `--opponent {all,random,untrained,baseline,selfmirror}`、`--mode {mirror,cross}`；`run_one` 返回 `wins/losses/decided/draws/errs/illegal{clamp,forfeit,…}/draw_breakdown{turn_cap,max_steps,true_draw}/winrate/winrate_ci95/length/games_per_s` |
| `scripts/h2h_ckpt.py` | `ckpt_a ckpt_b games` + 池/权重/种子；**不输出非法动作计数** |
| `runs/evaluation/final_gate/run_h2h_instrumented.py` | 正是为上面这点写的包装：monkey-patch `TwoSidedSelfPlayEnv.step` 统计 `illegal_clamp/illegal_forfeit` |
| `scripts/ft_gate_ckpt.py` | `ckpt base games --deck-csv --opp-json --opp-weights {counts,uniform} --base-key`，`--base-key net_b` 可取两网 ckpt 的对手网 |

### 3.2 缺陷 1（严重）：`baseline` 对手是硬编码常量，传 `--base` 无效

`eval_h2h.py:46-47`：

```python
CAND_CKPT = os.path.join("runs", "train-20m-e16-1m", "ckpt_999424.pt")
BASE_CKPT = os.path.join("runs", "train-20m-e16-1m", "ckpt_500736.pt")
```

`build_opponent` 里 `kind == "baseline"` 分支直接 `load_net(BASE_CKPT, …)`，**完全不看传入的 `cand_path`**。所以如果我按直觉把 `a.base` 当参数传进去，G7 会静默地拿 `ckpt_500736` 当对手去比——比错对象且标签写着 `baseline_ckpt_500736`，很难被发现。

修法（三件事一起做）：

```python
h.CAND_CKPT = os.path.abspath(a.ckpt)
h.BASE_CKPT = os.path.abspath(a.base)
...
if label == "vs_old_ckpt":
    assert os.path.abspath(r["meta"]["ckpt"]) == os.path.abspath(a.base)
    assert r["meta"]["step"] == base_step
```

顺带修掉第二个隐患：那两个常量是**相对路径**，依赖 CWD；`--out`/评测从别的目录启动就会加载失败或加载到错文件。改成绝对路径后 self-test 的断言通过，证明机制生效。

### 3.3 缺陷 2：`--quick` 自检模式会把跳过项误报 FAIL

第一次 self-test 输出 `[FAIL] G2_agent接口 / G3_测试`——其实是因为 `--quick` 根本不跑 smoke 和 pytest。改为 `pass=True` + `"skipped": True` + 打印 `SKIP`，并强制 `promote = (not a.quick) and all(...)`，避免"自检通过"被误读成"门禁通过"。

### 3.4 缺陷 3：`vs 未训练` 这一格按 §2.3 的机制不可信

G6 原来只看合并胜率。改成"**跨 ≥2 个随机初始化合并 + Wilson 下界 > 0.5**"，并把每个初始化的点值写进 `per_init_wr`，同时在 JSON 里留下原因说明。

### 3.5 新增 G7b：held-out 交叉臂

原矩阵只有混合池 cross，而真实比赛里双方牌组本就不同。G7b 让候选驾驶 `best_deck.csv`、旧模型驾驶 **44 副 held-out 牌组**（见 §4），判定用"Wilson 下界 > 0.40"的非劣界（判断值，已在代码注释里写明主提升门是 G7 同牌组镜像，这一臂只用于排除"仅在自家牌组上变强"），并记录同型对照参照 `0.508`（既有 74 副池，注明池不同仅作量级参考）。

### 3.6 self-test 记录

`phase4_gate.py --quick` 跑了三次（`phase4_gate_selftest{,2,3}.json`），全部走通：4 个镜像臂 + 1 个交叉臂、G1–G8 全部产出、`SKIP` 标注正确。用 `ckpt_999424` 当候选时 `G7 FAIL`（0.25/4 局）属预期噪声——self-test 验证的是代码通路，不是结论。

另外核实 `eval_h2h.load_net` 只读 `ck["net"]`，因此**无论交回 `ckpt_*.pt`、`latest.pt` 还是 `best.pt` 都能评**；并为两网 ckpt（含 `net_b`）加了 `ckpt_keys` 留档，用 `weights_only=True` 读取、失败则标记 `<unreadable-under-weights_only>`（响应安全提示，不启用任意对象反序列化）。

## 5. 工作包 D：阶段 1 收尾审计

任务书 §四 的清单里有三项此前只做了推断，本轮补成实证。

### 5.1 OptionType / SelectType / SelectContext 覆盖

| 维度 | 结论 | 证据 |
|:---|:---|:---|
| OptionType 0..16 | **全覆盖**。`N_OPT_TYPES = 17`，每种占一个 one-hot 槽；`_pyopt()` 显式映射 13 种带字段的（0,3,4,5,6,7,8/9,10/11,13,15,16）；其余 4 种（1 YES / 2 NO / 12 RETREAT / 14 END）按规则本就无附加字段，落到只带 `type` 的默认分支是正确行为 | `enc_constants.py:27`、`encoding.py:150-165` |
| SelectType | 标量特征 `select_type` 进编码 | `encoding.py:99,945,1001` |
| SelectContext 0..48 | 标量特征 `select_context`，容量 `N_SELECT_CTX = 64` **过量分配**，`min(context, 63)` 的钳制永不触发 → 无上下文坍缩损失 | `enc_constants.py:30`、`encoding.py:1231` |
| `contextCard` / `effect` | 各 2 槽并带 `effect_mask`，缺位时掩码置 0 | `encoding.py:946,1235` |

结论表述方式：Agent 是学习型策略，"覆盖所有 SelectType/SelectContext"体现为**每种类型都有特征通道 + 类型无关的合法掩码**，而不是逐类型手写分支；上表逐项确认没有类型落到未处理路径。

### 5.2 不访问对手隐藏手牌

全包内 `get("hand")` 仅 3 处，逐处定位到玩家索引：

| 位置 | 读取对象 | 判定 |
|:---|:---|:---|
| `encoding.py:1290` | 己方 `mp` → `self_hand_id/mask`；紧邻注释 "opp hidden -> handCount UNK tokens" | ✅ |
| `encoding.py:450` | 己方 `mp`（`decklist_drawable_flags(decklist, s, mp)` 形参） | ✅ |
| `search_agent.py:61-62` | 受 `with_hand` 控制：`:124` 对己方 `with_hand=True`，`:100` 对对手 `_observed(op, stadium, 1-me, with_hand=False)` | ✅ |

对手手牌在观测里的唯一来源是公开信息的信念推断（`hand_beliefs_for()` 只收 `zone==HAND` 的揭示日志，再用 UNK 补齐到 `handCount`），并且有 `_enforce_hand_count()` 维持"已知在手信念数 ≤ 实际手张数"不变量。→ 不存在读取 `players[1-yourIndex]["hand"]` 的路径。

### 5.3 退化 select（`option` 为空且 `minCount≥1`）——判为无缺陷，不加投机兜底

追踪 `encoding.build_mask`（L125-148）得到返回值安全性的完整证明：

1. 已选项被排除（`if i not in picked`）→ `sorted(set(picked))` 不会因重复而变短
2. `submit` 仅在 `min_c ≤ len(picked) < max_c` 合法 → 长度必然落在 `[minCount, maxCount]`
3. 掩码全零时兜底放行 `submit` → `agent()` 随即 break 返回 `[]`
4. 掩码只把下标开放到 `i < min(len(option), MAX_OPTIONS)` → **下标越界在构造上不可能**

已知边界（非缺陷，留档）：`option` 数超过 `MAX_OPTIONS` 时被截断，代码用 `_note_opt_overflow` 计数上报。实测触发次数：本会话所有观测（840 + 1,620 局口径、Windows 964+ 决策、Linux 1,127 步）均为 **0**；该分支的真实引擎行为仍属**推断**（从未被触发）。

### 9.4 近零字节探测定位上限（已执行并验证）

原理：带 `Expect: 100-continue` 时 nginx 依据 `Content-Length` 在**读 body 之前**判定，收到判定即断开，不传输任何 body（`probe_body_limit.py`，全程 0 写入）。

| 声明长度 | 响应 |
|---:|:---|
| 1024 KiB | `100 Continue`（放行） |
| 1100 / 1200 / 1500 / 2000 / 2048 / 2049 KiB、2 / 5 / 10 / 20 / 32 / 50 / 64 / 72 / 100 / 128 MiB | 一律 `413` |

→ 上限就是 nginx 默认 `client_max_body_size 1m` = **1,048,576 B**，且算的是**整个 multipart body**，故 `submission.tar.gz` 本体须 **≲ 1,047,000 B**。

**连带后果**：四个"已通过门禁并完成哈希校验"的 71.6 MB 提交包**一个都上传不了**；`model.pt` 单项 81 MB 即超 78 倍。此前所有会话的"导出成功"结论都成立，但**"可交付"从未被端到端验证过**——这正是任务书 §九 要求区分"已执行/已验证/未执行/推断"的价值所在。

1. **三者的 CI 大面积重叠**（已验证：数值区间）→ 在"对随机合法策略"这一口径上，**20.3M 训练网络相对 38.4 万随机初始化网络没有可检出的优势**。
2. **随机初始化本身方差极大**（小网 0.383↔0.850）→ 任何单 seed 的"vs 未训练 / vs 随机"数字都不能单独作强度结论，必须跨初始化合并（与 §11 的 R1 一致）。
3. **因此 1 MiB 上限不是决定性损失**（推断，基于 1、2）；真正未解释的是**A 榜累计第一 0.797 vs 我们最好的一格 0.617**（口径不同，见 §9.2 警告，只可定性比较）—— 差距更可能在牌组与策略结构，而这只能从真实对局数据里学（§9.5 那条被 502 卡住的路）。

### 10.4 蒸馏链路为何不是开箱可用（已核实）

- `scripts/bc_train.py` 支持 `--d-model/--nhead/--nlayers/--ff` 覆盖 ✅，但它是**离线 BC**，位置参数要 `.npz` 或 `.npy` 目录
- `scripts/build_bc_from_zips.py` 需要 Kaggle replay `.zip`；**本机无任何 `.npz`/`.zip` 数据集**（`find` 核实）
- `rl/rollout.py` 只有 `collect_rollout` 等库函数，**不是 CLI**，没有现成的"从教师 ckpt 导出 BC 数据"脚本

三条可选路线（训练一律由你运行）：
